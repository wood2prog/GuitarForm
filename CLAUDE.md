# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

GuitarForm is a guitar designer: a Rhino 8 plug-in written in C#. A dockable panel has a tab for each section of the guitar (instrument, body, soundhole, and later neck, fretboard, strings and so on). Designs and per-section presets are stored in a SQLite library, previewed live in Rhino, and built into the document on request.

## Working agreement

- The user gives the design direction for each section. Implement what they describe, and ask instead of guessing at guitar geometry, or at a section's fields, that haven't been specified.
- `IMPROVEMENTS.md` is the ordered checklist of project-organization work. Tick items off as they're done.

## Build

```
dotnet build GuitarForm/GuitarForm.csproj
```

- This is a Rhino 8–only project. It uses the `RhinoCommon` NuGet package (8.0.x, `ExcludeAssets="runtime"`), targets `net7.0-windows` (Rhino 8 runs it on its current .NET runtime), and outputs `GuitarForm/bin/Debug/net7.0-windows/GuitarForm.rhp`.
- `Directory.Build.props` (repo root) holds the settings every project shares (`LangVersion`, `NoWarn` NETSDK1138); a project adds its own warnings with `$(NoWarn);...`.
- It builds for `win-x64` only, so SQLite's native `e_sqlite3.dll` lands next to the `.rhp`: Rhino doesn't search `runtimes/<platform>/native/` for a plug-in.
- The launch profile (`GuitarForm/Properties/launchSettings.json`) starts Rhino 8 with the build folder in `RHINO_PACKAGE_DIRS`, so the plug-in loads without being installed, and runs the `GuitarForm` command, which opens the panel. Start Rhino for testing from PowerShell, not Git Bash, which rewrites `/`-arguments into paths.
- Tests: `dotnet test GuitarForm.Tests`. They cover the model, the library and the geometry (NUnit plus Rhino.Testing, which loads the installed Rhino 8; the test project targets `net8.0-windows` to match Rhino 8's current runtime). Add tests when the model, library or geometry changes, and keep the Quick Test values in `docs/` and the tests in agreement. The panel, preview and Build still need checking in Rhino.
- Test classes that use RhinoCommon types need `[RhinoTestFixture]`. Don't capture RhinoCommon structs (e.g. `Point3d`) in lambdas in test code: the compiler-generated closure class makes NUnit load RhinoCommon before Rhino is set up, and no tests are found. The test project references the model, geometry and data projects; don't compile the geometry sources into it, for the same reason.

## Projects

- `GuitarForm.Model`: the design model. `GuitarDesign` holds one record per section (`Instrument`, `Body`, `Soundhole`). Plain records, no Rhino dependency, lengths in mm, optional values nullable. `DesignDocument` is the JSON export and import: change `DesignDocument.SchemaVersion` whenever the JSON's shape changes, and keep reading older versions.
  - The replacement model is being built alongside it, CAD-neutral and with no geometry: `Parts/` (`Guitar` → `Neck` (fretboard, nut, headshape; refers to a library `Fretwire` and `StringSet`) and `Body` (top plate with its bracing, back plate)). The neck, body and bracing are each saved on their own in the library so another guitar can reuse them and `Parameters/` (a `ParameterDefinition`, shared by every guitar, and one guitar's value for it, which formats, parses and checks itself). Every definition matches `docs/Glossary.md`, and `PartTests` checks that. `GuitarDocument` is its JSON export (schemaVersion 3: values by abbreviation, lists as arrays, separately saved parts nested by kind; it converts version 1 design documents and ignores the neck profile values older versions saved). The library, panel and geometry still use `GuitarDesign` until they're moved over.
- `GuitarForm.Shapes`: the replacement geometry, CAD-neutral (no Rhino): 2D points, lines, arcs, circles and paths in mm, worked out from a `Guitar`. `PlateShape` (the outline as a chain of slots, clockwise from the top of the centerline, in open pieces until every value is set, then one closed path; plus the cutaway), `SideViewShape`, `SoundholeShape`, `FretboardShape` (plan view over the plate: outline, frets, slots, face dots, strings), `FretboardSideShape` (its profile in the side view), `NeckSideShape` (the neck under the fretboard in the side view: shaft, heel, heel cap and nut), `NeckProfilesShape` (the neck's cross-sections at the first and selected frets and through the heel, beside the side view), `BracingShape` (the top's blocks and braces on a copy of the plate seen from inside, left of the plate) and `GuitarDrawing`, which lays them out and tags its output (`GuitarDrawing.Items`, each a `DrawnItem` with a `DrawingComponent` and a `DrawingRole`). Until the panel is reworked, `NewFields` holds the new-model values the old sections lack (shown in groups on the Body tab and the Bracing, Fretboard and Neck tabs), per design in `NewFields/<id>.json` beside the library. Errors that the model's `Validate` reports stop a shape without a message of their own; shapes report only what the model can't see. Its tests are plain NUnit, with no Rhino. The plug-in still draws through `GuitarForm.Geometry` until it moves to the new model, when `GuitarForm.Geometry` becomes the adapter that turns shapes into Rhino curves.
- `GuitarForm.Geometry`: the geometry maths (RhinoCommon, no UI). `ComponentStyles` (with `ComponentStyle`) lives here, internal and visible to the plug-in and the tests, with `ApplyNewLayerStyle` for a new layer's colors. It is the adapter that turns shapes into Rhino curves. `DesignDrawing.FromShapes` wraps a `GuitarDrawing` as curves, keeping construction geometry apart from the final outline and messages per section; its `Curves` carry the `GuitarDrawing` tags. The legacy classes (`PlateGeometry`, `SideViewGeometry`, `SoundholeGeometry`, `DesignDrawing.Draw`) are deleted; `CustomSoundholeGeometry` remains for the planned custom soundhole. `DesignUnits` converts between mm and document units.
- `GuitarForm.Data`: the SQLite library, no Rhino dependency. `Library` stores designs and presets, and for the new model (`Library.Parts.cs`) guitars, the neck, body and bracing they own, named copies of those, and the fretwire and string sets necks refer to: one `parts` row per part saved on its own, and its values in `part_values` by glossary abbreviation, so a new setting needs no migration; `Schema.cs` holds the tables and migrations (never edit a released migration; add a new one); `SectionTables` maps each section to its table; `Backups` backs up, prunes and restores; `RecoveryStore` keeps one recovery file per design for unsaved work (outside the library, never over it); `GuitarFormSettings` is the plug-in's settings record.
  - Library upgrades first copy the file beside it as `<name>.before-v{N}.bak`; a failed copy blocks the open.
- `GuitarForm`: the plug-in. `GuitarFormPanel` (design list, the working copy with Save, Save as and Revert, the unsaved-changes prompts, section tabs, Preview and Build), `SectionEditor` with the fields declared in `Sections.cs` and the collapsible Messages bar below the tabs, `NumberSlider` (the fader-style box for every decimal field; choices and yes/no values get a `FieldDropDown` from the parameter's `OptionTexts`, counts a plain box), `SettingsPage`, `DesignPreview` (display conduit), `DesignBuilder`, `BackupScheduler`, and `UiMetrics` (shared spacing, widths and theme-aware colors; use it rather than literal sizes or colors). The Strings tab (`StringsTab`, with `StringSetEditor`) edits the library's string sets, and the Frets tab (`FretsTab`, with `FretwireEditor`) its fretwires in the same way, sharing `LibraryItemUi`. The "Show strings" preference is a plug-in setting, not part of a design. Edits change only the working copy (`_design` and `_newFields`) and mark it dirty; nothing reaches the library until Save. `RecoveryStore` gets the dirty copy on a short timer and when the panel hides or Rhino closes, and the copy is offered back when that design is next opened.

## Conventions

- The guitar is drawn vertically: the origin is the tail end of the body and the body length runs along +Y.
- Lengths are stored in mm (database, presets, JSON, geometry). Every length the user sees or types in the plug-in (fields, dialogs, settings, messages) is in the active document's units, converted with `DisplayUnits`.
- A design owns its own copy of each section. A preset is a named section in the library; loading it copies its values into the design.
- Adding a section, or a field to one, touches: its record in `GuitarForm.Model` (and `GuitarDesign`), a migration in `Schema.cs` and its columns in `SectionTables`, its geometry class and `DesignDrawing` if it draws anything, its fields in `Sections.cs` and a tab in `GuitarFormPanel`, its `docs/` page, and tests (round trips in `LibraryTests` and `DesignDocumentTests`, plus the geometry). A value goes in `Instrument` only when the user says it belongs to the whole instrument.
- Build puts objects on the `Guitar` layer tree: `Guitar::Body`, `Guitar::Neck` and `Guitar::Fretboard`, each with one sublayer per component, plus a light gray `Construction` sublayer per group. Every component name, layer path and color is in the single `ComponentStyles` table (`GuitarForm.Geometry/ComponentStyles.cs`): change a component there, nowhere else. The preview draws each curve in its component's color (construction light gray, centerlines thinner), so it matches Build. An existing layer's color is left alone: it is set only when Build creates the layer. Build removes the old `GuitarForm::Outline` and `GuitarForm::Construction` layers when they are empty (never an object). Built objects are tagged with the design's id (`DesignBuilder.DesignIdKey`), so building again replaces only that design's objects. A future Colors tab (global, kept in the plug-in settings: a display color and an optional print color mapped to the layer's PlotColor) will override the table. The `DrawingComponent` enum names are permanent keys: never rename one, only add.
- Each tab is documented in `docs/` (fields, geometry and a Quick Test), with a row in the README's tabs table. The README stays an overview: requirements, build, loading, using the panel and shared conventions.
- The plug-in's GUID (`Properties/AssemblyInfo.cs`) and the panel's GUID (`GuitarFormPanel`) are permanent; never change them.
- The project logo is `GuitarForm/Resources/Source/GuitarForm.png`, scaled to `Resources/Icons/GuitarForm.png` (24x24, the panel icon). Keep full-size artwork in `Resources/Source/`. When shrinking line art to 24x24, thicken or boost the line first, or it fades to almost nothing.
